# Git tag and release convention

## Versioning rule
Use Semantic Versioning: `MAJOR.MINOR.PATCH`.

For this release:
- package version: `0.1.0`
- Git tag: `v0.1.0`
- GitHub release title: `PlasRip v0.1.0`

## Tag format
Always create annotated tags in the form:

```bash
git tag -a v0.1.0 -m "PlasRip v0.1.0"
```

Do not use bare numeric tags like `0.1.0` for GitHub releases. Keep the `v` prefix consistent.

## Recommended release commit sequence
```bash
python scripts/check_version_sync.py
git status
git add .
git commit -m "release: v0.1.0"
git tag -a v0.1.0 -m "PlasRip v0.1.0"
git push origin main
git push origin v0.1.0
```

## Suggested GitHub release assets
- Source code archive generated by GitHub
- `RELEASE_NOTES_v0.1.0.md` copied into the GitHub release description
- Optional prebuilt conda package artifact from `conda build conda.recipe --output`
